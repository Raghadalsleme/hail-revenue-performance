# منصة تنمية الإيرادات البلدية ومتابعة أداء الإدارات
**Smart Municipal Revenue Growth & Department Performance System — Prototype v1.0.1**

> **نموذج أولي للعرض — غير معتمد رسميًا من أمانة منطقة حائل.** (تظهر هذه الحالة في تذييل كل صفحة وفي تذييل تقارير PDF.)
> **Synthetic Data — بيانات تجريبية لا تمثل أرقام أمانة منطقة حائل.** الأسماء الإدارية تجريبية ولا تمثل الهيكل التنظيمي للأمانة.

منصة ويب عربية (RTL) مبنية بـ Python وStreamlit تجمع بين:

1. **تحليل الإيرادات واكتشاف فرص زيادتها** من بيانات الأصول والعقود والمستحقات، مع تقدير مساهمة كل فرصة في سد فجوة السنة الحالية.
2. **متابعة الأداء الشهري للأقسام** لمدير الإدارة العامة بألوان حالة واضحة مصحوبة بنصوص.

---

## ما الذي يعمل فعليًا

| الصفحة | ما تقدمه |
|---|---|
| لوحة الإيرادات | المستهدف، المحقق حتى تاريخ اللقطة، الفجوة، نسبة التحقيق، الإيراد الأساسي المتوقع، الفجوة المتوقعة بنهاية السنة، الإيرادات حسب المصدر، ومساهمة الفرص المختارة (القيمة المختصرة بالمليون والقيمة الدقيقة ظاهرة دائمًا). |
| فرص الإيرادات | محرك قواعد يستخرج الفرص من البيانات (أصول غير مستغلة، تجديد عقود أقل من المرجع السوقي، تحصيل متأخرات)، مع الأدلة وطريقة الحساب بالأرقام والافتراضات والمهلة والسهولة والمخاطر والموافقات، وقائمة «ما الذي استُبعد ولماذا». |
| السيناريوهات | اختيار الفرص يدويًا أو تلقائيًا، سيناريو متحفظ/متوسط/متفائل (70%/100%/120% قابلة للتعديل)، الفجوة المتبقية والفائض، منع التكرار والتعارض وتطبيق السقوف. |
| أداء الإدارات | بطاقات الأقسام (درجة، حالة ملونة مع نص، التغير عن الشهر السابق، سبب التصنيف، المؤشرات غير المحققة)، أقسام تحتاج متابعة، اتجاه الأداء، خريطة الحالة الشهرية، جدول مقارنة، وتفاصيل مؤشرات القسم. |
| إدخال بيانات الأداء | إدخال/تعديل شهر، تعديل أسماء الإدارات والأقسام بمعرفات ثابتة، إضافة أقسام وإدارات، استيراد CSV/Excel بتحقق كامل، قوالب، نسخ احتياطي واستعادة. |
| البيانات والإعدادات | تاريخ اللقطة والمستهدف والأساس المالي، افتراضات المحرك، استيراد بيانات الإيرادات بتحقق ذري، القوالب، قاموس البيانات. |
| التقارير | تقرير PDF عربي وملف Excel للإيرادات (السيناريو المختار والفرص المختارة مميزة)، وملخص أداء الشهر والإدارة بصيغتي Excel وPDF. |
| المنهجية | كل المعادلات والافتراضات وحدود النموذج وما يلزم قبل الاستخدام الرسمي. |

**الذكاء الاصطناعي:** لا يوجد نموذج تعلم آلة مدرب في هذا الإصدار، لعدم توفر بيانات تاريخية حقيقية. المحرك قواعد تحليلية قابلة للتفسير، والبنية تسمح بإضافة نموذج لاحقًا (انظر `core/opportunities.py`).

## النتائج على البيانات التجريبية (للتحقق السريع)

- المستهدف 100,000,000 ريال، المحقق حتى 30 سبتمبر 2026: 80,000,000 ⇒ الفجوة حتى اللقطة 20,000,000 (80%).
- الإيراد الأساسي المتوقع لبقية السنة 11,500,000 ⇒ **الفجوة المتوقعة بنهاية السنة 8,500,000**.
- 27 فرصة مكتشفة و12 عنصرًا مستبعدًا. الاختيار التلقائي (20 فرصة) في السيناريو المتوسط يحتسب 3,402,439 ريال (متكرر 134,535 + تحصيل لمرة واحدة 3,267,904) ⇒ **تبقى فجوة 5,097,561 ريال**. المتحفظ 2,152,726 والمتفائل 4,221,328 — الفرص لا تكفي في أي سيناريو، والمنصة تعرض ذلك صراحة.
- أداء «الإدارة العامة التجريبية (أ)» لشهر سبتمبر 2026: جيد 2، متوسط 2، يحتاج تدخل 1، بيانات ناقصة 1؛ متوسط المكتملة 84.5%.

## التشغيل على جهاز Mac

**الأسهل:** انقر نقرًا مزدوجًا على `run_mac.command` (أول مرة يثبّت المكتبات تلقائيًا ثم يفتح المتصفح). إذا رفض macOS فتحه: انقر بزر الفأرة الأيمن ← «فتح».

**أو من Terminal:**

```bash
cd hail-platform
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
streamlit run app.py
```

يتطلب Python 3.12 أو أحدث. للاستخدام دون Terminal ودون إبقاء جهازك مفتوحًا: انشر المشروع على Streamlit Community Cloud — الخطوات في [`docs/DEPLOYMENT.md`](docs/DEPLOYMENT.md).

## الحفظ والبيانات

- **افتراضيًا (وفي النسخة المنشورة): ذاكرة الجلسة فقط.** المنصة تقول ذلك صراحة في الترويسة وصفحة الإدخال. استخدم «تنزيل نسخة احتياطية كاملة» ثم «استعادة» لاحقًا.
- **حفظ محلي اختياري (SQLite)** لبيانات الأداء عند التشغيل على جهازك: `HAIL_LOCAL_DB=data/local/performance.db streamlit run app.py`. يُحفظ كل تعديل بكتابة ذرية. لا يُستخدم في النسخة المنشورة لأن خوادمها مشتركة ومؤقتة.
- **بيانات الأداء منفصلة عن بيانات الإيرادات**؛ رفع إحداهما لا يمس الأخرى.
- **وضع العرض** مفعّل افتراضيًا ويرفض أي بيانات موسومة `real`. للتشغيل الداخلي على بيانات حقيقية: `HAIL_DEMO_MODE=0`.
- البيانات التجريبية تُولد حتميًا: `python scripts/generate_synthetic_data.py`.

## الشعار

الشعار في `assets/logo/hail_logo.png` هو الملف الذي زوّدنا به صاحب المشروع، بعد قص الهوامش الفارغة فقط دون أي تعديل على الشكل أو الألوان أو النسب (النسخة كما وصلت محفوظة في `hail_logo_as_provided.png`). يظهر تلقائيًا في الترويسة وتقارير PDF. يُنصح بمطابقته مع النسخة المعتمدة لدى الأمانة قبل أي عرض رسمي.

## لماذا Streamlit مع CSS مخصص

بقي المشروع على Streamlit كما طُلب، مع إخفاء عناصره الافتراضية وبناء ترويسة وشريط تنقل وبطاقات وجداول بـ HTML/CSS مخصص. الحدود المعروفة: شبكة إدخال البيانات (data editor) ترسم من اليسار لليمين فعُكس ترتيب أعمدتها، والتنقل يتم داخل الجلسة نفسها. إذا احتاجت الأمانة لاحقًا تحكمًا كاملًا بالتصميم أو صلاحيات متعددة المستخدمين، فالبديل المقترح هو واجهة مستقلة (مثل React أو Next.js) فوق واجهة برمجية بـ FastAPI تعيد استخدام وحدات `core/` كما هي — ولم يُنفذ هذا التحويل.

## قبل أي استخدام رسمي

بيانات حقيقية معتمدة من الأنظمة المالية وسجل الأصول والعقود والتحصيل؛ مراجع سوقية من مقيّمين معتمدين؛ معايرة الافتراضات ببيانات تاريخية؛ اعتماد الأوزان وحدود التصنيف؛ نظام دخول وصلاحيات وسجل تدقيق؛ قاعدة بيانات مؤسسية؛ استضافة داخلية متوافقة مع متطلبات حماية البيانات؛ ومراجعة نظامية لكل فرصة. التفاصيل في [`docs/METHODOLOGY.md`](docs/METHODOLOGY.md).
